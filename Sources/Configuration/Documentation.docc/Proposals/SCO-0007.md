# SCO-0007: Batch updates in MutableInMemoryProvider

Update multiple values of a `MutableInMemoryProvider` in one atomic step.

## Overview

- Proposal: SCO-0007
- Author(s): [Raluca Coutinho](https://github.com/RalucaP)
- Status: **In Review**
- Issue: [apple/swift-configuration#19](https://github.com/apple/swift-configuration/issues/19)
- Implementation:
    - [apple/swift-configuration#232](https://github.com/apple/swift-configuration/pull/232)


### Introduction

Add `setValues(_:)` to set a batch of values in one call, and `withValues(_:)` to read and change values while the provider is locked.


### Motivation

Currently, `MutableInMemoryProvider` changes values one at a time, with `setValue(_:forKey:)`, and notifies watchers after each change. This makes it hard to:

- Apply related changes together, for example when bridging another configuration system. Watchers can see a half-updated configuration, such as a new database host with the old port.
- Test what happens when a configuration file reloads and many values change at once.
- Change a value based on its current value. Reading and writing it are separate calls, so a change that another task makes in between can be lost.

### Proposed solution

We propose adding `setValues(_:)`, which takes the new values as a dictionary. Keys that aren't included keep their current values, and `nil` removes a value:

```swift
provider.setValues([
    "database.host": "db-a.example.com",
    "database.port": 5433,
    "database.timeout": nil, // Removes the value
])
```

We also propose adding `withValues(_:)`, which passes the stored values to a closure that can read and change them while the provider is locked:

```swift
provider.withValues { values in
    if values["database.host"] == "db-a.example.com" {
        values["database.host"] = "db-b.example.com"
        values["database.port"] = 6432
    }
}
```

With either method, a snapshot has all of the changes from one call, or none of them. To see related values change together, read them from one snapshot.

### Detailed design

```swift
extension MutableInMemoryProvider {
    /// Updates the stored values for multiple configuration keys at once.
    ///
    /// This method atomically applies all the updates, so a snapshot never contains some
    /// of the updates without the others. Watchers of a changed key receive its new value
    /// once. If any value changed, snapshot watchers receive one snapshot that contains all
    /// the updates. If a new value is the same as the existing value, no notification is
    /// sent for that key. Keys not included in `values` keep their current values.
    ///
    /// - Parameter values: A dictionary that maps configuration keys to their new values,
    ///   or to `nil` to remove a value entirely.
    public func setValues(_ values: [AbsoluteConfigKey: ConfigValue?])

    /// Reads and updates the stored values in a single atomic operation.
    ///
    /// The body runs while the provider holds its lock, so no other reads or updates happen
    /// until it finishes. It edits the stored values in place: if the body throws, the changes
    /// it made before the error are kept. When the body returns or throws, watchers of changed
    /// keys receive their new values, and snapshot watchers receive one snapshot that contains
    /// all the changes.
    ///
    /// Don't call the provider, or a ``ConfigReader`` that reads from it, from inside the
    /// body. The lock isn't recursive, so the call crashes or deadlocks.
    ///
    /// - Parameter body: A closure that reads and modifies the stored values.
    /// - Returns: The value that `body` returns.
    /// - Throws: Rethrows any error that `body` throws.
    public func withValues<Return: ~Copyable, Failure: Error>(
        _ body: (inout [AbsoluteConfigKey: ConfigValue]) throws(Failure) -> Return
    ) throws(Failure) -> Return
}
```

`setValues(_:)` calls `withValues(_:)`. Like `setValue(_:forKey:)`, both methods notify watchers after releasing the lock. `withValues(_:)` saves the old values of watched keys before it calls the closure. When there are snapshot watchers, it also keeps the whole dictionary to tell whether anything changed, which can cost one copy when the closure first changes a value.

### API stability

This change is purely additive, so existing providers and adopters aren't affected.

### Future directions

None at the moment.

### Alternatives considered

- Discarding the changes when the closure throws. This would make `withValues(_:)` all-or-nothing, but could copy all the values on every call that changes something.
- Notifying snapshot watchers after every `withValues(_:)` call, without comparing the values. This would avoid keeping the whole dictionary, but would send a snapshot even when nothing changed, as `ReloadingFileProvider` does after each reload.
